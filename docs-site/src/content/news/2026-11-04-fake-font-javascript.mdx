A file such as `public/fonts/fa-solid-400.woff2` that is not a font is one of
PolinRider's ways in ([PolinRider is A/B Testing its Way Past Your Detections][osm-ab]).
It holds JavaScript, and a VS Code task runs it with Node.js the moment the
folder is opened and trusted ([DPRK Contagious Interview "Fake Font" Abuses VS Code Tasks][osm-jan]). A real font starts with
the four bytes `wOF2` or `wOFF`, so you can tell the two apart without opening
the project. If you find a fake, treat the computer that opened the project as
infected.

## How the trick works

Two files work together.

- **The "font".** It sits where web fonts live, usually under
  `public/fonts/`, and is named like a Font Awesome file:
  `fa-brands-regular.woff2` in the January sample
  ([January post][osm-jan]), `fa-solid-400.woff2` in the PolinRider cases
  OpenSourceMalware described from April on
  ([PolinRider DPRK Attack Expands Across GitHub][osm-april]; [A/B Testing][osm-ab]).
  Inside is JavaScript, not a font.
- **The task.** `.vscode/tasks.json` holds a task, typically labelled
  `eslint-check`, set to run when the folder opens (`"runOn": "folderOpen"`)
  with its output hidden. Its command runs the font with Node.js
  ([January post][osm-jan]; [A/B Testing][osm-ab]).

Node.js does not care about a file's extension, so it runs the code
([GhostAction Copycats PolinRider][osm-ghostaction]). The trick also works on
people: a fonts folder looks normal in a web project ([January post][osm-jan]),
and a font reads as a binary file, which scanners skip
([PolinRider Jumps the Fence][osm-fence]) and most manual review passes over
([A Developer's Guide to Getting Rid of PolinRider][osm-guide]).

OpenSourceMalware described the trick in January 2026, in fake job
interview repositories handed to developers as coding tests
([January post][osm-jan]). In April it found the PolinRider loader inside
`public/fonts/fa-solid-400.woff2` in one repository with no `tasks.json` at
all, and on that evidence wrote that "the fake-font playbook is now part of
PolinRider's standard kit"
([PolinRider DPRK Attack Expands Across GitHub][osm-april]).

It has also turned up in npm packages and Go modules. As OpenSourceMalware
reports it, JFrog found two npm packages with a VS Code task that ran a
JavaScript file named `public/fonts/fa-solid-400.woff2`, and Nextron found 16
Go modules carrying the same file, with matching SHA-256 hashes. Neither
report named PolinRider; tying them to the campaign is OpenSourceMalware's own
reading of the shared techniques
([PolinRider Caused Dozens of npm, Go, PHP Compromises][osm-go]).

## The name keeps changing

Searching for one file name is not enough. Across 2026 OpenSourceMalware saw
these names in one organization's three repositories. They did not simply
replace each other: the 400 variant reached only two of the three, and at the
end of 25 September the 500 and 900 variants were both running
([A/B Testing][osm-ab]).

| Name | First seen |
|---|---|
| `fa-solid-400.woff2` | 25 April |
| `fa-solid-500.woff2` | 3 September |
| `fa-solid-900.woff2` | 25 September |
| `fa-solid-300.llf` | 28 September |

Three things changed besides the number.

- **`fa-solid-900.woff2` is a genuine Font Awesome file name.** While the 400
  and 500 variants were in place, a real 79,444-byte WOFF2 file of that name
  sat next to the fake in the same folder; in the 900 variant the fake takes
  the name. The name alone proves
  nothing either way.
- **`.llf` is not a font extension at all**, so a check that only reads
  `.woff2` files misses it.
- **The folder moved.** On 25 September the fake landed several levels deep
  inside existing folders, a different path in each repository: one under
  `prisma/generated/prisma/internal/public/fonts/`, the other two under
  `src/.../dto/public/fonts/`.

All three points are from the same post ([A/B Testing][osm-ab]).

The contents vary too. In January OpenSourceMalware analysed 14 of the
repositories and found 11 different payloads among them, from 1,489 to 147,449
bytes ([January post][osm-jan]). Many 400 payloads and both 500 builds start
with long runs of whitespace (273 tab characters in one 500 build, 421 in the
other), so a quick look at the file shows nothing. The 900 payload starts
straight with code ([A/B Testing][osm-ab]).

## Copied by another group

In October OpenSourceMalware found the GhostAction campaign using a copy of
the launcher to run a credential stealer and install a cron job. It keeps
the task label `eslint-check`, the `folderOpen` trigger and a Font Awesome
name under `public/fonts/` (`fa-solid-400.woff2`), and adds presentation
options of its own (`isBackground`, `hide`, `echo: false`, `close: true`). There the "font" is 38 lines of plain Node.js.
OpenSourceMalware found no shared indicators of compromise with any DPRK
malware it has seen, and so, "at this time", labels it a copycat
([GhostAction Copycats PolinRider][osm-ghostaction]). For you it means the
same check finds both, and both need the same response.

## Telling a real font from a fake

Do this from a terminal, without opening the project in an editor.

1. **Look at the first four bytes.** The WOFF 2.0 specification requires every
   WOFF2 file to start with the signature `wOF2`, and WOFF 1.0 requires
   `wOFF` ([W3C WOFF 2.0][w3c-woff2]; [W3C WOFF 1.0][w3c-woff]).

   ```bash
   head -c 4 public/fonts/fa-solid-400.woff2; echo
   ```

   Anything else in a `.woff2` or `.woff` file means it is not that font.
2. **Ask what the file is.** On the January sample, `file` reported
   "JavaScript source, ASCII text, with very long lines (19828), with no line
   terminators" ([January post][osm-jan]).

   ```bash
   file public/fonts/*
   ```

3. **Read `.vscode/tasks.json` as text.** A task that runs `node` on a font
   file, or anything set to `"runOn": "folderOpen"` that you did not write,
   is the launcher ([A/B Testing][osm-ab]).
4. **Search the whole tree, not one folder,** for `fa-solid-*` files and for
   `.llf` files.

Two harmless cases look like fakes. A Git LFS pointer is a short text stub
that stands in for a font, and a placeholder can be an empty file. Neither has
font bytes and neither is malware
([False positives you will see](/polinrider-cleaner/docs/reference/false-positives/)).

Never run the file to see what it does. Running it is the infection.

## If you find one

1. **Do not open the folder in VS Code.** If VS Code asks whether to trust it,
   say no. If it asks whether to allow the folder's automatic tasks, choose
   Disallow ([A/B Testing][osm-ab]).
2. **Treat any computer that opened the project as infected**
   ([PolinRider Jumps the Fence][osm-fence]), and check it before anything
   else ([Order matters](/polinrider-cleaner/docs/guides/order/)).
3. **Look for the rest.** The same repository can also carry a payload
   appended to a config file such as `eslint.config.mjs`, which runs without
   VS Code at all, whenever anything loads the config: a lint run, a commit
   hook, a CI job ([A/B Testing][osm-ab]). Remove the fake font, the task and
   the appended payload together.
4. **Then clean the repository and rotate credentials** in the order the
   guides give ([A machine](/polinrider-cleaner/docs/guides/machine/);
   [A personal GitHub account](/polinrider-cleaner/docs/guides/account/)).

## What polinrider looks for

- Every `.woff` and `.woff2` file is read, and one whose first bytes are not a
  font's is a confirmed finding. Git LFS pointers and empty files are skipped.
- Fake fonts published by their hash are recognised even if they start like a
  font.
- `fa-solid-NNN.llf` is a confirmed finding by its name.
- A `fa-solid-` font named for a weight Font Awesome does not ship, and
  `public/fonts/fa-solid-900.woff2`, are listed for review, because a name
  alone is not proof.
- A task that runs `node` on a `fa-solid-NNN.woff2` file is a confirmed
  finding.

The reasons for each entry are in
[`ioc/filenames.txt`](https://github.com/meSingh/polinrider-cleaner/blob/main/ioc/filenames.txt),
[`ioc/filenames-review.txt`](https://github.com/meSingh/polinrider-cleaner/blob/main/ioc/filenames-review.txt)
and [`ioc/strong-patterns.txt`](https://github.com/meSingh/polinrider-cleaner/blob/main/ioc/strong-patterns.txt),
and in the
[2026-09-28](/polinrider-cleaner/news/indicator-reviews/2026-09-28/) and
[2026-10-05](/polinrider-cleaner/news/indicator-reviews/2026-10-05/) indicator
reviews.
