PolinRider is malware that hides inside software projects. Once it runs on a
developer's computer, it steals their passwords and tokens, adds itself to
the code they work on and pushes that code with their own account, so the
next person who opens the project is hit too. Security researchers link it
to North Korea ([OpenSourceMalware][osm-march]; [The Hacker News][thn]).

Its goal is not your code. The code is how it travels. The goal is your
logins and your money.

## Am I at risk?

You could be if you write code and, in the last year or so, you did any of
these:

- installed an npm, Go or Composer package;
- installed a VS Code or Cursor extension;
- opened someone else's project in your editor, including one you cloned to
  review;
- did a "take-home" coding test for a job interview.

None of these is unusual, which is the point. A check takes a few minutes:
[install and run polinrider](/docs/quick-start/).

The last one matters most. **Opening the folder is enough.** You do not have
to run the project, install anything or click anything
([OpenSourceMalware][osm-march]; [fake fonts][osm-ab]).

## What it does on your computer

First a small piece of hidden JavaScript runs. It fetches the real malware
from records stored on public blockchains, which means there is no single
website to block or take down ([OpenSourceMalware][osm-march];
[SafeDep][safedep-eth]).

That second part is built to steal. Reports name the DEV#POPPER remote
access tool and the OmniStealer password stealer ([The Hacker News][thn]).
What it goes after:

- passwords and logged-in sessions saved in your browser;
- GitHub tokens and SSH keys, and the login of the `gh` command;
- npm, cloud, database and CI tokens;
- every secret in every `.env` file it can read;
- cryptocurrency wallets and their recovery phrases.

Then it spreads. It adds itself to the projects on your computer and pushes
them to GitHub with your account. In one case researchers watched an
operator at the keyboard, installing a stealer and a clipboard monitor by
hand ([Deception.Pro][dp]).

## Why your Git history looks clean

This is why people miss it. A small script on the infected computer,
`temp_auto_push.bat`, rewrites your last commit and pushes it again
([OpenSourceMalware][osm-march]):

1. It reads your last commit: its date, message and author.
2. It **winds the computer's clock back** to that commit's date.
3. It adds the malware to that commit, keeping your name and message.
4. It puts the clock right and force-pushes the branch.

So the commit looks exactly as it did before. Your name, your message, the
original date. Reading `git log` will not show you anything wrong.

What it cannot change is GitHub's own record of the push. GitHub writes down
every push and force-push with the account that made it and the real time,
and none of that comes from the commit ([How to investigate a repo's real
history][osm-history]).

<HistoryCompare />

That record is how polinrider finds the clean version to go back to. GitHub
keeps it for a limited time, so check early. Once the record is gone, the
infected commit can only be cleaned, not undone.

## Signs to look for

Each of these is something you can see in a project or on your computer.
[Found something? Is it PolinRider or a false alarm?](/news/2026-11-04-polinrider-or-false-alarm/)

<div class="tgrid tgrid-2">
<div class="tcard">
<p class="tcard-title">A font file that is really code</p>

A file such as
`public/fonts/fa-solid-400.woff2` that holds JavaScript instead of a font. A
real `.woff2` font starts with the letters `wOF2`. The names keep changing
([fake fonts][osm-ab]; [our post](/news/2026-11-04-fake-font-javascript/)).
</div>
<div class="tcard">
<p class="tcard-title">An editor task that runs when you open the folder</p>

A `.vscode/tasks.json`
with `"runOn": "folderOpen"`, often labelled like a normal tool such as
`eslint-check`, with its output hidden ([fake fonts][osm-ab]).
</div>
<div class="tcard">
<p class="tcard-title">Code after the end of a config file</p>

In `postcss.config.mjs`,
`tailwind.config.js`, `eslint.config.mjs` and similar, extra code after the
real end of the file, often pushed far to the right by a long run of spaces
([OpenSourceMalware][osm-march]).
</div>
<div class="tcard">
<p class="tcard-title">temp_auto_push.bat</p>

, in a project or listed in a `.gitignore` nobody on
your team wrote. It means a computer that pushes to that project is infected
([our post](/news/2026-11-04-temp-auto-push-bat/)).
</div>
<div class="tcard">
<p class="tcard-title">It keeps coming back</p>

Your antivirus removes it and it is back the next
time you run `npm run dev`. Something that starts it has not been found yet
([our post](/news/2026-11-04-polinrider-keeps-coming-back/)).
</div>
<div class="tcard">
<p class="tcard-title">MicrosoftSystem64</p>

running on your computer, or folders named
`.pcl-data` and `.pcl-state` in your home folder. That is related malware,
below.
</div>
</div>

## Related malware: MicrosoftSystem64

`MicrosoftSystem64` is a remote-access tool installed by malicious npm
packages. It is related to PolinRider through the group behind it, not part
of PolinRider itself. SafeDep places the packages that install it in a
cluster that kmsec.uk and OX Security link to Famous Chollima, also called
Contagious Interview, a group tied to North Korea ([SafeDep][safedep-ms64]).
OpenSourceMalware considers PolinRider a parallel or sub-campaign of
Contagious Interview ([OpenSourceMalware][osm-blast]). No report we have
read calls `MicrosoftSystem64` a PolinRider payload.

polinrider checks for it too, because it targets the same developers and
needs the same response: a program or process named `MicrosoftSystem64`, and
the folders `~/.pcl-data` and `~/.pcl-state`.
[MicrosoftSystem64 on your computer](/news/2026-11-04-microsoftsystem64/) has
the detail.

## Why cleaning once is not enough

If you clean GitHub while an infected computer still holds a valid token, the
malware pushes itself back within minutes. That is why the order is fixed:
check every computer first, change every password and token, then clean the
repositories, then scan every future push.
[Order matters](/docs/guides/order/).

## What polinrider looks for

Every indicator traces to a public source. They sit in plain files anyone can
read: file names, text in files, package names, network addresses, file
hashes and the paths the related malware uses. A confirmed match means
infection; a match a normal project could also have is shown for you to
review. [The full indicator set](/threat/indicators/).
