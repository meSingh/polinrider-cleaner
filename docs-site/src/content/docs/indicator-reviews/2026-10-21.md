## Upstream state

The dossier has not moved in fifteen weeks. No primary analysis of PolinRider
was published between 2026-10-19 and 2026-10-21 that this review could find.

- **OpenSourceMalware, "Glassworm Hacks OVH Clouds CLI tool", 2026-10-19.**
  Release binaries of five `ovh/ovhcloud-cli` versions were replaced through a
  contributor account that GlassWorm had held since March, with a ForceMemo
  style amend-and-force-push in that account's own repositories. The post says
  in so many words: "We found no PolinRider markers, no malicious workflow
  additions and no GhostAction indicators." Nothing here for `ioc/`. It is
  recorded because it lands under the `ForceMemo` search the routine runs, and
  because the history-rewrite technique is the same one this tool already
  checks for.
- **`html-to-gutenberg` is still being poisoned.** The OpenSSF record
  MAL-2026-6359 was updated on 2026-10-19 with three versions the 2026-10-05
  review could not have seen: **4.2.24 (2026-10-11), 4.2.25 and 4.2.26
  (2026-10-17)**, imported from GHSA-2gqj-wrf5-35w8. The record's Amazon
  Inspector section describes this package's payload as the
  `fa-solid-500.woff2` folderOpen loader reading the `0xa322` wallet, which is
  PolinRider. The registry agrees: all three were published by the same single
  maintainer account, `digelim`, and have been removed; `latest` is still
  4.2.10. So the publisher account, or the release automation behind it, was
  still in the attacker's hands four days ago, five weeks after the last
  malicious release the set recorded. `fetch-page-assets`, from the same
  account, has had nothing new since 1.2.16 on 2026-08-30. The hijacked-versions
  comment in `bad-packages.txt` is updated to say so; the name itself stays a
  comment, because 4.2.10 and earlier are clean.

### Two June package names this set never carried

The `MicrosoftSystem64` search returned summaries naming `utils-terminal@3.2.1`
and `logger-active@3.2.1`. Neither is in `ioc/`, in any earlier review, or in
the OpenSSF database. The summaries were not used; the names were traced to
their primary source and read there:

- **Microsoft Threat Intelligence, post on X, 2026-06-03**
  ([status 2062013269687054695](https://x.com/MsftSecIntel/status/2062013269687054695)),
  read through Twitter's public syndication endpoint: "Compromised npm packages
  (utils-terminal@3.2.1, logger-active@3.2.1) are abusing Hugging Face repos as
  exfiltration infrastructure. The packages deploy a remote access trojan (RAT)
  that captures keystrokes, screenshots, and crypto wallet credentials." The
  attached image carries no text.
- ToolsLib's write-up of the same post (2026-06-04) names the RAT as
  `MicrosoftSystem64`, the npm publisher as `hexalpha10` and the author field as
  `toskypi`, the same author as `eo-terminal` and `logger-draft` (added
  2026-10-12) and SafeDep's whole js-logger-pack cluster. That is secondary and
  was not used for any line, but it is what ties these two to this set rather
  than to some other RAT.

On `registry.npmjs.org` on 2026-10-21 both are the `0.0.1-security`
placeholder. Each was first published as 3.2.0 on 2026-06-01, followed by 3.2.1
and 3.2.2 on 2026-06-03, and taken down the same day. There is no earlier
history, so despite Microsoft's word "compromised" these are attacker-created
names, not hijacked ones, and under the rule since 2.1.0 the name alone is a
finding.

## Considered and not added

**`logger-active` in `bad-packages.txt`.** It is the same kind of name as
`logger-draft`, which went into `bad-packages.txt` on 2026-10-12, and the two
could reasonably be treated alike. It went to `weak.txt` because "active" is a
UI state: `className="logger-active"` or a `'logger-active'` string in a
Tailwind safelist stands as a whole name, and the GitHub checks would call that
repository INFECTED. A CSS selector `.logger-active` does not (a dot is part of
a name to the whole-name matcher), but the weak tier is a substring match, so
`ci/scan-workspace.sh` does put a review line on it. That is the cost of review
tier and it was accepted. The maintainer may want to overrule this, or to move
`logger-draft` the other way for consistency.

**`c2-toskypi.onrender.com`.** Listed by ToolsLib as a network indicator from
Microsoft's post. It is not in the post's text, and the post's image carries
none; the list may come from a reply thread this review could not read. A
secondary source only, so not carried. It would be a `network.txt` line if a
primary source confirms it.

**`hexalpha10`.** The npm publisher account, per ToolsLib only. An account
name is not something a scan of files would find.

**The `microsoftsystem64` crate on crates.io**
([RUSTSEC-2026-0102](https://rustsec.org/advisories/RUSTSEC-2026-0102)). Nine
versions published 2026-04-09, removed for an SSH `authorized_keys` backdoor and
file and Telegram `tdata` exfiltration, reported by Socket and sitsh. It shares
the implant's name in lower case, and the `authorized_keys` behaviour matches
the `toskypi` RAT. But the advisory names no actor and no source reachable here
connects it to PolinRider, and `bad-packages.txt` is checked against npm
manifests, not `Cargo.toml`. Recorded so the next reviewer does not re-derive
it; worth carrying if a source ties it to the campaign.

**Everything in the OVH post**: the GlassWorm Solana wallet, the `HassenBF`
account, the replaced release assets. A different actor by the source's own
statement.

**The other 63 OpenSSF records.** Already in `ioc/`, in its comments, or in
pull request #55.

is `"global['!']"`, the `strong.txt` marker `global['!']` with its first
letter escaped, exits 2 under both `polinrider check --fs-only` and
`ci/scan-workspace.sh`. **Closed**, by 2.1.0 and ADR-0040.

re-confirmed with this week's weak entry: `polinrider check --fs-only` on a
manifest that depends on `logger-active` exits 0 with no review line, and
`ci/scan-workspace.sh --fail-on review` on the same folder exits 1 with one.
That makes this week's classification matter more than usual: on the machine
and folder checks, `logger-active` is invisible.

**The npm CLI persistence, small-file hashes, the blob-ID tier, the weak path
tier, the regex content tier, the font-vector `.woff2` forms, Python-side
