## Upstream state

The dossier has not moved. The new material is Island's write-up of a cluster
this set already carries in part: the ULID-impersonation npm packages
(`ulid-xyz`, `pino-ulid` and others) that install the `MicrosoftSystem64` agent.
Island follows them from the npm side to 88 public GitHub repositories (9,881
stars, 65,681 forks in total) themed as AI agents, trading, finance and
healthcare tools, each pulling the dropper in through a dependency. The
repositories are victims' or throwaway projects, not indicators; see below.
The persistence artifacts Island lists (`MicrosoftSystem64.vbs`, the
`com.launchkeeper` LaunchAgent, the systemd user service) were already carried.

## Considered and not added

- **`pretty-logger`.** Island lists it, but it is a live package published in
  2014 by one maintainer, with no scripts and 26 downloads a week. Almost
  certainly named as a dependency name collision or victim, not attacker-owned.
  Not added to any file.
- **`ioredis-typed` and `ioredis-orm`.** OpenSSF marks both malicious
  (MAL-2026-5676, MAL-2026-5675) and npm has replaced both with the placeholder.
  `ioredis-orm` is a verbatim ioredis copy whose only addition is a dependency on
  `ioredis-typed`. Nothing I read ties them to the campaign: no source names
  PolinRider, `MicrosoftSystem64` or a shared C2, and OpenSSF's own text calls the
  carrier clean and the transitive unproven. Same naming style and the same weeks
  as the cluster, so likely, but not added on a likelihood.
- **`instrumentation-ioredis`.** An unrelated 2024 malicious record that happens
  to contain "ioredis".
- **`.pkg-agent.lock`.** Named by Island as a host artifact, with no directory.
  `implant-paths.txt` matches whole paths and the file's location is unknown, so
  any entry would be a guess.
- **`bootstrap-commits.sh`.** A generic name that legitimate repositories can use.
- **The 87 listed GitHub repositories and their owners** (`Cesarjoquin`,
  `Stormeye85` and the rest). They are other people's or throwaway repositories,
  not artifacts on a machine, the rule since 2026-09-21. The list is the input
  for a GitHub-side check a person would run, not for `ioc/`.

- **`authorized_keys`, the blob-ID tier, the weak path tier, the regex content

## New techniques — maintainer decisions, not implemented

1. **Dependency-chain reading in lockfiles.** This cluster hides behind a
   package that looks like a copy of ioredis, with the dropper two dependencies
   deep. The binary already reads package names from lockfiles, so a name in
   the chain is caught once it is listed. A name that has not yet been
   reported is not, and nothing flags "a copy of a well-known package that adds
   one unrelated dependency".
2. **GitHub-side matching of dependency names.** Island found the repositories
   by their dependency. The GitHub checks read `package.json` on each ref, so
   adding names here already covers them; no new check is needed. Recorded so
   nobody builds one.
