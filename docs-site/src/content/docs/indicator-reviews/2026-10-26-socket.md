## How each package was classified

Every npm name was read on registry.npmjs.org the same day, for its version
count, its first publication, whether npm has replaced it with the
`0.0.1-security` placeholder, and its weekly downloads.

- **Attacker-owned**: npm's placeholder, or fully unpublished, with no history
  before the malicious versions. Carried by name.
- **Infected legitimate packages**: years of clean releases and real users.
  Not carried by name, which would alarm every user of them; the malicious
  versions are listed in a comment, as for `html-to-gutenberg`.
- **Victims' repositories**: the Go modules and the Composer packages are other
  people's GitHub repositories, published as modules from infected branches
  (`dev-master`, `dev-fix/remove-malware`, Dependabot branches). Not indicators
  of anything in someone else's project, the rule since 2026-09-21.

## Considered and not added

**Eighteen infected legitimate npm packages**, listed with their malicious
versions in a comment in `bad-packages.txt`: `qrcode-vue3` (16k downloads a
week), `@joyfill/components`, the `itsa-react-*` family and `itsa-utils`
(published since 2016), `@testrelic/*`, `@react-native-aria/separator`,
`revine`, `spoint`, two templates and two chatbot widgets. The tool compares
package names, not versions, so these are a lockfile check for a person.

**Two crates**, `greentic-setup` and `greentic-setup-dev`, dev builds of a real
project. Recorded in the same comment.

**Two Chrome extensions**, the "one Chrome extension" earlier reviews could not
name, now two: ExpertAI Dev (`nafkmlanpinblehjeebdjaolelielbgc`), malicious 1.0.1
and 1.0.2, and CM Hub (`mfdgcmogddhinoaechjhfjmjcahljpie`), malicious 1.0.17. Both
are legitimate extensions with clean later versions. Nothing in `ioc/` can
match an installed browser extension: Chrome keeps them under `~/Library` on
macOS, which the walk does not enter. See techniques.

**140 Go modules and 19 Composer packages.** Victims' repositories, as above.

## New techniques — maintainer decisions, not implemented

1. **A browser-extension check.** Read Chrome's, Edge's and Brave's
   `Extensions/<id>/<version>_0/` folders in each profile, as the editor
   extension check reads VS Code's, and match an extension ID and version
   against a list. It would carry the two extensions above.
2. **Version-aware package matching.** The infected legitimate packages above
   are a finding only at their malicious versions. `src/manifest.rs` already
   reads package names out of lockfiles; reading the version beside each would
   let these be carried as `name@version`.
