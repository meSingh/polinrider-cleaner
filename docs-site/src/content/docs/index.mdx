<section class="pr-section">

## Clean up in this order

<ol class="pr-steps">
<li><strong>Check every computer</strong><span>that touched the affected repositories, before GitHub.</span></li>
<li><strong>Rotate every credential</strong><span>from a computer you trust.</span></li>
<li><strong>Clean the repositories</strong><span>restore where the evidence survived, clean where it did not.</span></li>
<li><strong>Scan every future push</strong><span>so CI catches a reinfection.</span></li>
</ol>

Cleaning GitHub while an infected computer still holds a valid token undoes
the work within minutes. [Why the order is fixed](/polinrider-cleaner/guides/order/)

</section>

<div>

## What it will not do

- **Prove you are clean.** Signatures change. Rotate your credentials anyway.
- **Make an infected computer safe again.** Quarantine contains it. A clean
  reinstall recovers it.
- **Change anything you did not agree to.** Every fix is a dry run first.
  Nothing is deleted: confirmed files are moved to quarantine.

</div>

<div>

## Why you can run it

- **Built during a real incident** on the author's own account: 57
  repositories and 304 refs. Two of ten restore points were infected too.
- **Indicators reviewed every week,** and [every review is published](/polinrider-cleaner/indicator-reviews/).
- **Every commit is signed.** Every release carries build provenance.
- **It scans itself** in CI, against its own indicators.

[Check all of this yourself](/polinrider-cleaner/reference/verifying/)

</div>
