# 0004. node_modules is not scanned

| | |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-09-06 |

## Context

A dependency tree is enormous, largely identical across machines, and scanning it turns a fast check into a slow one.

But PolinRider ships malicious npm packages, so this is precisely the campaign where skipping `node_modules` costs something.

## Decision

`node_modules` stays excluded from the file scan. Installed package **names** are matched against `ioc/bad-packages.txt` in every manifest and lockfile instead.

When the scanner sees a `node_modules` directory it says so in its output, naming what is not covered and how to override it.

## Consequences

A declared malicious dependency is caught by name. A package placed there by hand, or pulled in transitively without appearing in a lockfile, is not.

`--exclude ''` scans it anyway, slowly.

The disclosure appears only when a `node_modules` directory actually exists, so it is information rather than noise.
