Verified against fixtures before the pull request was opened: a `package.json`

`bsc-rpc.publicnode.com` returns `review`; and a `package.json` depending on the
real, popular `tailwindcss-animate` returns **zero findings** — fixed-string
matching means the longer malicious name matches only itself.

## Considered and not added

- **Obfuscator shuffle seeds** `2857687`, `2667686` (variant 1) and `1111436`,
  `3896884` (variant 2). The dossier's YARA rule uses them, but only in
  conjunction with a marker or a decoder name. `ioc/` is matched as fixed strings
  with no conjunction, so on its own each one flags any file containing that
  seven-digit number.
- **`global['r'] = require` and `global['m'] = module`**, the two strings the
  dossier's YARA rule treats as common across both variants. These are how you
  would catch a third variant that had rotated its marker, which makes them
  tempting, but the exact spacing is an artefact of one generator's output and
  minification breaks the match. This wants a regex check in the scanner, not a
  fixed string in `ioc/`, and that is a maintainer decision.

## Open gaps

**The July 2026 ecosystem expansion is not in `ioc/` at all.** Socket counted 162
malicious release artifacts across 108 packages spanning npm, Packagist, Go
modules and one Chrome extension, and Checkmarx documented the ChainVeil and
ViteVenom npm clusters that OpenSourceMalware then attributed to this actor. The
main README's scale table already records the counts; not one of those package
names is matchable by the scanner.

This is the largest known hole in the indicator set. Nothing from it was added
here because the package lists were behind the review environment's egress
allowlist, and an indicator that was not read from its source does not belong in
`ioc/`. Closing it needs a deliberate pass from a machine that can reach the
Socket and Checkmarx reports, not a weekly sweep.

## Notes

- No page or repository read during this review attempted to give the reviewer
  instructions.
- The commits on #30 were written through the GitHub contents API and came back
  **unsigned**: that API applies GitHub's web-flow signature only for GitHub App
  installation tokens, and the review job authenticates as a user. The GraphQL
  `createCommitOnBranch` mutation, which always signs, is not available in the
  sandbox. #30 was squash-merged, which is the fix — GitHub builds and signs the
  squash commit itself, so `main` stayed fully verified. Squash is the merge
  method for these pull requests from now on.
